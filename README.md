# 🚀 PolicyPulse — GDPR RAG Assistant

PolicyPulse is a Retrieval-Augmented Generation (RAG) application for analyzing GDPR documents using **Meta Llama 3.3 Large Language Models (LLMs)**.

The system enables users to upload GDPR PDF files, retrieve semantically relevant text chunks, generate context-grounded answers, and verify whether generated responses are fully supported by the retrieved content.

The application combines semantic search, vector databases, and LLM-based reasoning to provide accurate and explainable responses for legal and regulatory queries.

---

# ✨ Features

- 📄 Upload and process GDPR PDF documents
- 🔍 Semantic search using vector embeddings
- 🧠 Context-aware question answering
- ✅ Automatic fact-check verification
- 📑 Retrieved chunk inspection with similarity scores
- 🎛️ Modern Gradio-based interface
- ⚡ Cosine similarity filtering for higher retrieval precision
- 🦙 Powered by Meta Llama 3.3

---

# 🛠️ Technologies Used

| Component | Technology |
|---|---|
| Frontend | Gradio |
| Backend | Python |
| Framework | LangChain |
| Vector Database | ChromaDB |
| Embeddings | HuggingFace Sentence Transformers |
| LLM Provider | Groq |
| LLM Model | Meta Llama 3.3 |
| PDF Processing | PyPDFLoader |

---

# 🧠 System Workflow

1. Upload GDPR PDF document
2. Extract document text
3. Split text into chunks
4. Generate vector embeddings
5. Store embeddings in ChromaDB
6. Retrieve relevant chunks using semantic similarity
7. Generate answer using retrieved context
8. Run fact-check verification
9. Display retrieved chunks and similarity scores

# 🦙 Large Language Model

The application uses **Meta Llama 3.3** through the Groq API for fast and efficient inference.

Llama 3.3 is responsible for:

- Context-grounded answer generation
- Understanding legal and regulatory language
- Producing accurate GDPR-related responses
- Supporting retrieval-augmented reasoning workflows

---

# 🧩 Core Components

## 📄 PDF Processing

The system uses `PyPDFLoader` to extract text content from uploaded GDPR PDF documents.

---

## ✂️ Text Chunking

Document text is divided into overlapping chunks using `TokenTextSplitter`.

Configuration:

```python
chunk_size = 500
chunk_overlap = 50
```

This improves semantic retrieval quality.

---

## 🧠 Embedding Generation

Embeddings are generated using:

```python
all-MiniLM-L6-v2
```

from HuggingFace sentence-transformers.

---

## 🗂️ Vector Database

Embeddings are stored in ChromaDB and retrieved using cosine similarity search.

---

## 🔎 Retrieval-Augmented Generation

The RAG pipeline:
- retrieves relevant chunks,
- constructs context,
- sends grounded prompts to Meta Llama 3.3,
- generates responses strictly from retrieved content.

---

## ✅ Fact Checking

A secondary verification chain evaluates whether the generated answer is fully supported by the retrieved context.

Possible outputs:
- VERIFIED
- WARNING

---

# 🎯 Similarity Threshold

Only chunks above the following threshold are used:

```python
SIMILARITY_THRESHOLD = 0.5
```

This reduces retrieval noise and improves answer relevance.

# 🖥️ Interface Overview

## 📥 Input Section

- PDF upload
- User question textbox
- Generate answer button

---

## 📤 Output Explanation

### Generated Answer

The final response generated by Meta Llama 3.3 using only the retrieved GDPR context.

---

### Verification Status

Displays whether the generated response is fully supported by the retrieved document chunks.

Possible values:
- VERIFIED
- WARNING

---

### Retrieved Chunks

Shows the text chunks retrieved from the vector database, including:

- Chunk ID
- Page Number
- Cosine Similarity Score
- Retrieved Text Content

These chunks represent the contextual evidence used during answer generation.
